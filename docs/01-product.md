# 01 — Product

## 제품 목표

> **팀 업무를 시각화한다. "지금 누가 뭐해?" 라는 질문이 사라지게 만든다.**

구두 보고, 메신저 ping, 회의 없이도 팀 전체 업무 현황을 한눈에 파악할 수 있는 웹앱.

---

## 페르소나

| 항목 | 내용 |
|------|------|
| 대상 | 10명 규모 스타트업 팀 리더 |
| 연령대 | 30~40대 |
| 상황 | 매일 아침 팀원 각자에게 진행 상황을 물어봐야 하는 비효율을 겪고 있음 |
| 니즈 | 로그인 후 30초 안에 팀 전체 상황 파악 |
| 고통 | 슬랙/카카오 메시지 수십 개를 읽어야 겨우 맥락 파악 가능 |

## MVP 범위

### 핵심 기능 — CRUD 4종 (모두 화면에서 동작)

| 기능 | 설명 |
|------|------|
| 추가 (Create) | 새 태스크 등록 — 제목, 상태, 마감 시각 입력 |
| 목록 (Read) | 전체 태스크 조회 및 상태별 필터 |
| 수정 (Update) | 인라인 또는 모달에서 제목·상태·마감 시각 변경 |
| 삭제 (Delete) | 개별 태스크 삭제 (확인 없이 즉시 또는 확인 모달) |

### 상태 분류

```
todo  →  in_progress  →  done
```

### 마감 시각 (due_at)

- 날짜만이 아닌 **날짜 + 시간** 까지 지정·표시
- 형식 예시: `2026-05-12 18:00`
- DB 저장: UTC `DATETIME`, 화면 표시: 로컬 타임존 변환

### UI / UX

| 항목 | 스펙 |
|------|------|
| 디자인 톤 | **macOS 스타일** — 둥근 모서리, 부드러운 그림자, 반투명 카드, 시스템 폰트 |
| 테마 | 라이트 / 다크 토글 — 선택값 `localStorage` 에 저장, 새로고침 후에도 유지 |
| 반응형 | 모바일 최소 **360px** 기준, 레이아웃 깨짐 없음 |

## 성공 기준 (Definition of Done — MVP)

| 항목 | 기준 |
|------|------|
| 데이터 유지 | 새로고침 후에도 태스크 목록이 그대로 남아 있음 |
| 반응형 | 360px 뷰포트에서 레이아웃 깨짐 없음 |
| API 응답 | 모든 CRUD 엔드포인트 **200ms 이하** |
| CRUD 동작 | 추가 / 목록 / 수정 / 삭제 4종 모두 화면에서 오류 없이 동작 |
| 테마 토글 | 라이트 ↔ 다크 전환 및 새로고침 후 상태 유지 |

## MVP 범위 외 (Out of Scope)

아래 항목은 MVP에 포함하지 않는다. 요청이 와도 확장 단계로 돌린다.

| 항목 | 이유 |
|------|------|
| 외부 결제 | 수익 모델 미확정 |
| 네이티브 앱 (iOS / Android) | 웹 우선 검증 후 고려 |
| WebRTC (화상/음성) | 인프라 복잡도 과다 |
| 외부 캘린더 연동 (Google, Outlook) | OAuth 범위 과다 |
| 파일 업로드 | 스토리지 설계 미포함 |
| WebSocket 실시간 동기화 | MVP는 **폴링** 방식으로 대체, 확장 단계에서 구현 |
